정책은 실행 경계에서 강제

기본 거부, 최소 권한, 하위 위임의 권한 부분집합, 입력·도구·출력의 분류와 검사를 설계 원칙으로 삼습니다.

모델과 도구는 신뢰 경계 밖

모델 출력은 실행 요청일 뿐 권한이나 승인이 아닙니다. schema → 권한 → 예산 → OS 격리 → 실행 → 출력 검사 → 감사 순으로 검증하며, 지원하지 않는 sandbox를 조용히 비격리 실행으로 바꾸지 않습니다.

PII와 비밀값

정보 분류와 금지 경로를 1차 방어로 두고 PII tokenization·최소 문맥·안전한 영수증을 설계합니다. 원문 프롬프트·도구 출력·비밀값은 로그·지식·메시지로 우회 보관하지 않습니다. 자연어 PII의 완벽한 탐지는 보장하지 않습니다.

취소·실패·권한 철회

정책 세대 변경, 임대 만료, 중복 전달과 불확실한 외부 쓰기를 별도로 처리합니다. 탐지기나 권한 검사 실패는 거부하고 감사 기록 실패는 새 효과를 막는 설계입니다. 실제 격리·교차 tenant·누출·취소 경쟁 시험은 구현 후 검증 대상입니다.
