하나의 제어면, 분산된 실행

초기 설계는 하나의 서버가 정책·세션·스케줄러·저장소의 정본을 소유하고 여러 워커가 작업을 가져가는 구조입니다.

CLI / HTTP / MCP → Policy · Budget → Workers → Evidence

실행 경로

CLI·HTTP·MCP 요청 → 인증·정책·예산 검사 → 실행 계획 → 로컬 또는 원격 워커 → 안전한 관측·체크포인트·영수증. 파일 읽기·편집·검색·격리된 shell과 action-observation loop를 기본 도구 계약으로 삼습니다. 같은 바이너리의 로컬 실행도 동일한 정책 경계를 따르도록 설계합니다.

저장과 장애 경계

SQLite와 PostgreSQL은 같은 논리 스키마와 계약 테스트를 목표로 합니다. 원격 워커는 서버 DB에 직접 접근하지 않으며 mTLS·작업 임대·세대 번호로 오래된 결과를 거부하는 설계입니다. 초기 단일 서버는 가용성 경계이며 고가용성 군집은 약속하지 않습니다.

잠정 자원 목표 · 미측정

CLI 시작 p95 ≤25 ms, 유휴 코어 RSS ≤32 MiB, 기본 stripped 바이너리 ≤15 MiB를 초기 목표로 제안합니다. 모델·네트워크·DB 초기화는 별도 경계로 보고하고, 브리지·지식 엔진·도구 프로세스까지 전체 비용을 합산해야 합니다.
