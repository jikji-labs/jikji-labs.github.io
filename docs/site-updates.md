# 사이트 갱신

톱은 리뉴얼 안내, `v1/`은 이전 버전 아카이브다. 진행 중인 설계는 `v2/`의 한국어 HTML이 정본이며 `v2/en/`에 같은 내용의 영어판을 함께 갱신한다. 정적 HTML/CSS이므로 빌드는 필요 없다.

1. 설계 문서 01~10, 요구사항 R1~R20과 실제 검토·구현·시험·측정 근거를 확인한다. 원문을 복사하지 말고 공개 가능한 요약을 작성한다. 비밀값·내부 주소·개인정보·비공개 경로는 넣지 않는다.
2. 해당 주제의 양 언어 페이지와 로드맵 진행 로그에 날짜·검증 결과·한계를 기록한다. 설계와 구현 완료를 구분하고, 수치는 목표/실측 및 측정 경계를 명시한다. 현재 모든 페이지는 “설계 단계 — 구현 전”이다. 상태 변경은 해당 근거가 있을 때만 한다.
3. `noindex,nofollow` 메타를 모든 진행 페이지에서 유지한다. 톱·v1·사이트맵·공개 탐색에 진행 사이트로 가는 링크를 추가하지 않는다. robots.txt에도 해당 경로를 적지 않는다. 이는 클릭 링크와 검색 노출을 줄이는 방식이며 접근 인증은 아니다.
4. `python3 scripts/verify_site.py`로 링크·HTML·아카이브 번역·공개 경계를 검증한다. 로컬 HTTP 서버에서 한국어/영어와 모바일 화면을 확인한다.
5. `git diff --check`와 gitleaks로 변경분을 검사하고, 의미 단위로 커밋한다. GitHub push 후 Pages 배포와 변경한 URL의 실제 내용을 확인한다. 검증하지 못한 것은 미실행으로 기록한다.

아카이브 검증은 `scripts/verify_v1.py`가 13개 로케일과 이전 콘텐츠 계약을 검사한다. v1의 과거 기능 설명은 현재 v2의 지원 약속이 아니다. 옛 HTML 경로는 대응하는 아카이브로 이동하고 fragment를 보존한다. CNAME은 유지한다.

## 요구사항 추적

| 요구 | 반영 주제 |
|---|---|
| R1 원본·Rust·GPL, R2 자원·온톨로지·다중 모델 | 개요, 아키텍처, 온톨로지, 모델 |
| R3 도구·루프·영수증, R4 실제 모델 비교 | 아키텍처, 모델, 로드맵 |
| R5 선택적 이전, R6 단일 바이너리·HTTP/MCP | 개요, 아키텍처, 로드맵 |
| R7 제한된 위임, R8 PII·권한·감사 | 모델, 보안 |
| R9 원격 워커, R10 단일 제어면, R11 두 DB | 아키텍처 |
| R12 연구 백본, R13 단계별 규모, R14 메시지·보드 | 개요, 에이전트 사회, 온톨로지 |
| R15 구독·예산 스케줄러, R16 관측 연계 | 모델, 운영 |
| R17 Lua/Python 확장, R18 예약 작업 | 개요, 에이전트 사회, 운영 |
| R19 선언형 workflow·정책·plugin 관리 | 에이전트 사회 |
| R20 한국어 대시보드·결재 | 운영 |

이는 요구의 설계 요약 추적이며 구현 완료 증거가 아니다. 설계 문서의 내부 운영 상세·비공개 통합 주소·권한 정보는 사이트로 옮기지 않는다.
